# services/evaluator — 신뢰도 필터 ①②③단계

## 왜 지금

수집기가 붙어 논문 3455편이 DB에 들어왔고, 사용자별 후보 107편까지 좁혀졌다.
지금까지 화면의 신뢰도 근거는 전부 가상 시드다. 이 작업이 끝나면 **실제 논문에
실제 근거 문장이 붙는다.** 큐레이션이 이 제품의 전부이므로, 여기가 제품의 핵심이다.

한 번 실행하면 아직 평가되지 않은 후보 논문을 가져와 ①규칙 ②출처 ③내용 순으로
거르고 `assessments`에 남긴다. 중간에 죽어도 다시 실행하면 이어서 진행한다.

## 이 설계를 정한 결정들

`docs/PRD.md` §3.2의 4단계 필터는 **저널 메타데이터를 전제로 쓰였다.** 실제 수집
결과는 그 전제를 만족하지 않는다 — 측정값은 `HISTORY.md` 참조.

| 관측 | 값 | 설계에 준 영향 |
|---|---|---|
| arXiv 논문 | 3455편 (전부 프리프린트) | ②단계가 지금 데이터만으로는 전부 동점 |
| DOI 보유 | 75편 (2%) | 철회 조회가 대부분 불가 |
| 후보 | 107편 | ③단계 LLM 비용의 상한을 정하는 수 |
| arXiv HTML 본문 | 제공됨, 논문당 약 27,000토큰 | ③단계가 본문을 볼 수 있다 |

여기서 네 가지를 정했다.

| 쟁점 | 결정 | 이유 |
|---|---|---|
| ②단계 데이터 소스 | **OpenAlex를 넣는다** | 이게 없으면 모든 논문의 ②단계 결과가 같다. 무료·키 불필요. 프리프린트의 저널 게재 여부도 여기서 알 수 있어 트랙이 갈린다 |
| 프리프린트 하루 2편 제한 vs 하루 4편 배달 | **제한을 지키고 편수를 줄인다** | 코퍼스가 100% 프리프린트라 둘은 양립 불가다. 절대 규칙 3을 굽히는 대신 "오늘은 믿을 만한 걸 2편만 찾았다"고 말한다. 다른 출처가 붙으면 자연히 4편이 찬다 |
| 작업 범위 | **①②③. ④는 미룬다** | 신선한 프리프린트는 인용·GitHub 스타가 0이라 ④가 변별하지 못한다. 반대로 ③이 없으면 어느 논문이 더 믿을 만한지 가릴 수단이 사실상 없다 |
| ③단계 입력 | **초록으로 좁히고 결선만 본문** | 하루 2편만 배달하므로 본문을 읽을 논문은 6편 안팎이다. 싼 필터가 앞에 오는 깔때기(CLAUDE.md) |

## 흐름

```
paper_candidates에서 assessments 없는 논문 (≈107편)
  │
  ├─ ① 규칙 필터            비용 0
  │    탈락 → assessments 기록하고 종료 (재평가하지 않는다)
  │
  ├─ ② OpenAlex 조회         무료, 논문당 1회
  │    트랙 결정: 저널 게재 → 검증 / 아니면 주목
  │
  ├─ ③a 초록 트리아지        LLM, 통과분 전체 (≈100편)
  │
  └─ ③b 본문 정밀 평가       LLM, 3a 상위 6편만
       arXiv HTML → 텍스트 → 루브릭 5항목 + 근거 문장
```

각 단계는 결과를 DB에 남긴다. ③b가 죽어도 ①②와 ③a 결과는 남고, 다시 실행하면
③b부터 이어간다.

## ① 규칙 필터 — 비용 0

| 검사 | 판정 | arXiv에서의 현실 |
|---|---|---|
| 철회 | DOI가 있으면 Crossref 확인. **DOI가 없으면 caveat이지 탈락이 아니다** | 2%만 조회 가능 |
| 약탈적·하이재킹 학술지 | `venue.kind === 'journal'`일 때만 블랙리스트 대조 | 지금은 해당 논문이 없다. 다른 출처가 붙을 때를 위한 자리 |
| 페이퍼밀 신호 | tortured phrases 사전을 초록에 대조 | 걸리는 게 드물지만 비용이 0이라 둔다 |
| 메타데이터 부실 | 초록 없음 · 200자 미만 · 저자 없음 · 제목 없음 | **PRD의 "DOI 없음"은 뺐다** |

> **PRD에서 바꾼 것**: PRD §3.2 ①은 "DOI 없음"을 메타데이터 부실로 본다. 그대로
> 적용하면 arXiv 논문의 98%가 탈락한다. 프리프린트는 저널에 실리기 전까지 DOI가
> 없는 게 정상이므로, 이건 부실이 아니라 **프리프린트의 정의**다. 탈락 사유에서
> 빼고 ②단계의 트랙 판정에 넘긴다.

탈락한 논문도 `assessments`에 `stage1.passed = false`로 남긴다. 다음 실행에서
같은 논문을 다시 평가하지 않기 위해서다. **`paper_candidates`에서 지우지는
않는다** — 후보는 관련성 단계의 출력이고, 신뢰도 판정은 별도 테이블의 일이다.
배달할 논문을 고르는 쪽(briefer)이 두 테이블을 조인해 `stage1.passed`를 본다.

## ② 출처 신호 — OpenAlex

arXiv id로 조회한다. polite pool을 쓰기 위해 `mailto`를 붙인다.

| 얻는 것 | `Stage2` 매핑 |
|---|---|
| `primary_location.source` (저널이면 그 저널) | `venueTier` — 저널명, 없으면 `null` |
| 게재 여부 | `reviewStatus` — `'published'` 또는 `'preprint'` |
| `cited_by_count` | `Stage4`로 갈 값이지만 ④를 미뤘으므로 근거 문장에만 쓴다 |
| `authorships[].author` 의 과거 실적 | `authorTrackRecord` — 0~1로 정규화 |

**`authorTrackRecord`의 가중치는 낮게 둔다** (PRD §3.2 ②, 명성 편향). 트랙 결정과
③단계 점수에 영향을 주지 않고, 근거 문장에서도 단독으로 쓰지 않는다.

**OpenAlex에 아직 없는 논문**(며칠 전 올라온 것이면 흔하다)은 탈락이 아니다.
`reviewStatus = 'preprint'`, caveat에 "색인 전이라 출처 신호를 확인하지 못했다"를
남기고 통과시킨다.

**트랙**: `reviewStatus === 'published'` → 🟢검증, 아니면 🟡주목.
①단계에서 탈락한 논문도 `track` 컬럼이 NOT NULL이므로 값이 필요하다 — 🟡주목으로
적되 `stage1.passed = false`가 진짜 상태다. 배달 후보를 고르는 쪽은 트랙이 아니라
`stage1.passed`를 먼저 본다.

### `field` 판정

`assessments.field`도 NOT NULL이다. arXiv 카테고리에서 규칙으로 정한다 —
`q-bio.*` → `bio_med`, `cs.*`·`stat.ME` → `cs`, 그 외 → `other`. 지금 코퍼스는
7개 카테고리뿐이라 이 매핑으로 충분하다. `social`은 해당 논문이 아직 없다.
분야별 가중치(PRD §3.3)를 넣을 때 이 값이 쓰인다.

## ③ 내용 평가 — LLM 2패스

프롬프트는 파일로 분리한다 (CLAUDE.md). 코드에 인라인하지 않는다.

### ③a 트리아지 — `prompts/triage.md`

①②를 통과한 후보 전체(≈100편)에 초록만 준다. 출력은 0~1 점수 하나와 한 줄 이유다.
여기서는 근거 문장을 UI에 쓰지 않는다 — 초록만 보고 만든 판단이라 근거로 내세우기에
약하다. 순위를 매기는 용도다.

### ③b 정밀 평가 — `prompts/deep-eval.md`

③a 상위 **6편**에만 돌린다. `fulltext.ts`가 arXiv HTML을 받아 텍스트로 만들고,
PRD §9의 루브릭 그대로 채점한다.

루브릭 5항목(`reproducibility` · `design` · `statistics` · `claimVsEvidence` ·
`limitations`)은 각각 `{ value, reason }`을 돌려준다. `Score` 타입이 이미
`value: number | null`을 허용한다.

**HTML이 없는 논문**(변환 실패, 오래된 논문)은 초록만으로 평가하되, 본문을 봐야
답할 수 있는 항목은 `value: null`로 두고 이유에 "본문을 확인하지 못했다"를 적는다.
**못 본 것을 봤다고 하지 않는다.**

### 절대 규칙 대응

- **규칙 1 (없는 수치를 만들지 않는다)**: 근거 문장에 등장하는 숫자와 고유명사를
  원문 텍스트와 대조하고, 대조에 실패한 문장은 버린다. 문장이 전부 버려지면 그
  항목은 `value: null`이 된다.
- **규칙 2 (점수 하나로 노출하지 않는다)**: 모든 단계가 `Evidence`에 근거 문장을
  남긴다. 이게 UI에 그대로 나간다.
- **규칙 4 (저작권)**: `fulltext.ts`가 받아온 본문은 **메모리에서만 쓰고 DB에
  저장하지 않는다.** 재실행하면 다시 받는다.

### 비용

| 항목 | 양 | 비고 |
|---|---|---|
| ① | 0 | 규칙만 |
| ② | 0 | OpenAlex 무료 |
| ③a | 약 5만 토큰 | 100편 × 초록 |
| ③b | 약 16만 토큰 | 6편 × 본문 27,000토큰 |

하루 20만 토큰대다. 본문을 읽는 논문이 6편이라 CLAUDE.md의 "LLM 본문 평가는
사용자당 하루 10~50편" 안쪽이다. 사용자가 늘어도 `assessments`는 논문당 1행이라
공유되므로, 비용은 사용자 수가 아니라 **후보 논문의 합집합 크기**를 따라간다.

## 스키마 변경

`assessments.stage3`와 `stage4`를 nullable로 바꾼다. 마이그레이션은 파일로 남긴다.

지금 ④는 만들지 않고, ③b는 6편에만 돌린다. 나머지 논문의 `stage3`·`stage4`는
**`null`이 정직한 값이다.** `stage4: { influentialCitations: 0 }` 같은 것을 넣으면
"인용 0회로 확인됨"으로 읽히는데, 실제로는 확인한 적이 없다 (절대 규칙 2).

화면 쪽 `apps/web/lib/trust-summary.ts`는 이미 `evidence`에 등장한 단계 수로만
분모를 잡으므로 손댈 것이 없다.

## 파일 구조

```
packages/core/src/
└── http.ts               collector에서 옮겨온다 (아래 참조)

services/evaluator/
├── prompts/
│   ├── triage.md
│   └── deep-eval.md
└── src/
    ├── index.ts          오케스트레이션 · 주입 가능한 의존성
    ├── stage1.ts         규칙 필터 (순수 함수)
    ├── stage2.ts         OpenAlex 조회와 매핑
    ├── stage3.ts         LLM 2패스
    ├── fulltext.ts       arXiv HTML → 텍스트
    ├── verify.ts         근거 문장의 수치를 원문과 대조 (절대 규칙 1)
    └── *.test.ts
```

**`http.ts` 이동**: 레이트리밋·재시도 래퍼를 `services/collector/src/http.ts`에서
`packages/core/src/http.ts`로 옮긴다. evaluator도 OpenAlex·Crossref·arXiv를
부르는데, 서비스가 다른 서비스를 import하게 두면 안 된다. `packages/core`가
"도메인 타입"이라는 성격에서 약간 벗어나지만, 55줄을 위해 패키지를 새로 만드는
것보다 낫다. collector의 import 경로를 함께 고친다.

## 상수 (`packages/core`)

```
TRIAGE_DEEP_CUT          6     ③b로 넘길 편수
STAGE1_MIN_ABSTRACT      200   이보다 짧은 초록은 메타데이터 부실
OPENALEX_MIN_INTERVAL_MS 100   polite pool 기준
EVAL_MAX_PER_RUN         200   한 실행에서 평가할 논문 수 상한
```

`TRIAGE_DEEP_CUT = 6`은 추측이다. 하루 2편 배달에 여유를 둔 값이고, **첫 실행
결과를 보고 조정한다.** 상수 주석에 그렇게 적는다.

## 실패 처리

논문 단위로 건너뛰고 로그를 남긴다. 파이프라인 전체를 죽이지 않는다.

- OpenAlex 조회 실패 → caveat 남기고 ③으로 진행
- 본문 받기 실패 → 초록만으로 평가, 해당 항목 `null`
- LLM 호출 실패 → 그 논문만 건너뛴다. 다음 실행에서 재시도된다
- 응답이 스키마에 맞지 않으면(zod 파싱 실패) 그 논문만 건너뛴다

수집기와 마찬가지로 `pg_try_advisory_lock`으로 중복 실행을 막는다.

## 테스트

| 대상 | 방법 |
|---|---|
| ①단계 | 순수 함수 단위 테스트. DOI 없는 논문이 통과하는지를 반드시 고정한다 |
| ②단계 | OpenAlex 응답 픽스처 파싱. 색인 전 논문(404) 처리. 실호출은 옵트인 |
| ③단계 | LLM 호출을 주입 가능하게 해서 가짜 응답으로. 스키마 위반 응답을 건너뛰는지 |
| `verify.ts` | 원문에 없는 수치가 든 문장이 버려지는지 |
| 전체 | 실제 실행 후 결과를 `HISTORY.md`에 기록 |

## 완료 기준

`pnpm pipeline:evaluate`가 exit 0으로 끝나고, `assessments`에 실제 근거 문장이
붙은 행이 생긴다. 한 번 더 실행하면 이미 평가한 논문을 다시 평가하지 않는다.
`pnpm typecheck` · `pnpm test` 통과. 결과(통과·탈락 편수, 트랙 분포, 근거 문장
샘플, 비용)를 `HISTORY.md`에 남긴다.

**첫 실행에서 확인할 것**: 수집기 단계에서 넘어온 `수면과 기억 공고화`의 후보
17편은 대부분 "기억"이라는 단어만 겹친 무관한 논문이다(`HISTORY.md` 2026-09-29).
**evaluator가 이걸 실제로 걸러내는지가 재현율 우선 설계의 첫 검증이다.**
걸러내지 못하면 관련성 단계로 돌아가야 한다.

## 이번에 하지 않는 것

- **④단계 (초기 반응)** — 신선한 논문은 인용·스타가 0이라 변별하지 못한다
- **프리프린트 후속 추적** (배달 2~4주 뒤 재확인) — PRD가 가장 큰 차별점이라고
  적은 기능이지만, 배달이 먼저다
- **분야별 가중치** (PRD §3.3) — 지금 코퍼스가 cs 중심이라 조정할 다른 분야가 없다
- **이의 제기 경로** (PRD §3.5) — 화면 쪽 작업
